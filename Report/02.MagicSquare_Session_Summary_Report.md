## 3. Mom Test 핵심 (STEP 1 요약)

### 진짜 문제

마방진 조건을 알고 있어도 제출 직전에 검증 항목(특히 대각선)을 빠뜨리고, 채점 실패 후 약 20분을 들여 우연히 누락을 찾아야 하는 불편이 반복된다.

### 표면 문제 (하지 않음)

Solver/Validator·ECB·GridUI **일괄 프로그램** 정의.

### 증거 3줄

1. 채점 실패 후 누락 찾기 **~20분**
2. 행·열 확인 후 **대각선 한쪽만** (또는 미검증)
3. **우연히** 누락 발견 — 체계적 10줄 재검증 아님

### 워크북 채점 (시뮬레이션 기준)

**8 / 10** — 보강 질문: 제출 직전 체크리스트에 **↘ ↙** 포함 여부.

## 4. 도메인 · Rule (`.cursorrules` 반영)

| 항목 | 규칙 |
|------|------|
| 격자 | 4×4 |
| 빈칸 | `0` **정확히 2개** |
| 값 | 1~16 |
| 마방진 상수 | **34** (MagicConstant SSOT) |
| 출력 | `int[6]` `[r1,c1,n1,r2,c2,n2]` — **1-index** |
| 검증 줄 | 10개 — R1–R4, C1–C4, ↘, ↙ |
| 오류 | E001~E007 boundary; entity는 E001~E005 **금지** |

## 5. 아키텍처 · Harness

### ECB 의존

```
boundary → control → entity
```

`entity → *` import 금지.

### Dual-Track TDD

| Track | 레이어 | Mock |
|-------|--------|------|
| Logic | entity, control | Domain Mock **금지** |
| UI | boundary | Mock **허용** |

### 테스트 명명 (Rule — 구현 예정)

- ID: `D-*` (Logic), `U-*` (UI)
- 파일: `test_d_*.py`, `test_u_*.py`

### Harness 현황

- `pytest --collect-only` → **0 tests** (골격만, exit 5 정상)
- 레거시 폴더 `tests/{entity,control,boundary}` ↔ 향후 `test_d_*` / `test_u_*` 병행·이전 예정
