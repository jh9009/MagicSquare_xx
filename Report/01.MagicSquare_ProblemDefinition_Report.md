## 1. 배경

4×4 마방진: 행·열·대각선 합이 동일(마법 상수 **34**). 1~16을 한 번씩 사용. 빈칸 2개(0)를 채워 완성.

ECB 설계 참고 (향후 단계):

| 계층 | 후보 |
|------|------|
| Entity | MagicSquare, Cell, SolveResult |
| Control | SquareValidator, MissingFinder, Solver |
| Boundary | GridUI, InputHandler, ResultDisplay |

**이번 STEP 1의 목표:** 프로그램 설계 전, Mom Test로 **진짜 문제**를 분리한다.

## 2. Mom Test 인터뷰 기록 (실제)

> 페르소나 답변 — 학습자 본인 과거 사실

### Q1. 마지막으로 손으로 풀어본 적은?

**답:** 지난주 OO 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데, 대각선 하나를 빼먹어서 20분 날렸다.

### Q2. 대각선 누락을 언제 알았는지?

**답:** 채점에서 실패해서, 누락된 부분을 찾다가 20분이 지나서 발견했다.

### Q3. 20분 동안 무엇부터 다시 봤는지?

**답:** 행/열 합이 맞는지는 확인했고, 한쪽 대각선이 비어 있는 것을 확인했지만 당연히 맞을 거라고 생각하고 놓쳤다.

### Q4. 제출 직전 대각선 합을 실제로 계산했는지?

**답:** 행·열 맞은 건 확인했고, 대각선은 한쪽만 하고 다른 쪽은 안 했다.

### Q5. 한쪽만 확인하고 멈춘 이유?

**답:** 한쪽만 맞으면 될 줄 알았다.

### Q6. 대각선 2개 필요함을 제출 전에 알고 있었는지?

**답:** 이미 알고 있었지만, 당연히 맞을 거라고 추측하고 넘어갔다.

### Q7. 제출 직전 "대각선 하나 더" 생각이 들었는지?

**답:** 아예 안 떠오르다가 시간이 지나고 생각나서 수정했다.

### Q8. 우연히 찾은 계기?

**답:** 20분 동안 뭔가 찾다가 우연히 찾았다.

## 3. Mom Test 시뮬레이션 (참고)

> **⚠️ 시뮬레이션** — 가상 페르소나. §2 실제 경험과 **혼동 금지**.

**페르소나:** 프로그래밍 수업에서 부분 마방진 과제를 받은 학생 (`Programming Basics`, Java `int[][]` 출력).

| Turn | 핵심 답변 |
|------|-----------|
| 1 | 손으로 7·8 채움 → Java 출력만. 검증 코드 없음. **행 합만** 대충 확인 |
| 2 | 대각선 **안 더함**. 행·열 맞으면 대각선도 맞겠지 |
| 3 | TA 피드백 후 **약 15분** — 행·열 재확인 후 슬라이드 재독으로 대각선 누락 인지. ↘ 대각선 36 |

**시뮬레이션 진짜 문제 (한 문장):**  
부분 마방진 조건을 슬라이드에서 읽었어도, 제출 전에는 행·열만 확인하고 대각선 검증을 생략해 TA 피드백 후 약 15분을 들여 누락 항목을 찾아야 하는 불편이 있다.

**시뮬레이션 증거 3줄:**

- 「TA한테 넘기기 전에 **행 합만** 대충 더해 봤어.」
- 「대각선은 **안 더했어.** 행·열이 맞으면 대각선도 맞겠지 하고 **넘겼어.**」
- 「**15분쯤** 슬라이드를 다시 열어보다가 **대각선을 안 본 것**을 알았어.」

## 4. Mom Test 결론 (실제 인터뷰 기준)

### 4.1 표면 문제 (잘못된 정의)

- 「4×4 마방진 Solver/Validator **프로그램을 만든다**」
- 「ECB로 MagicSquare·SquareValidator·GridUI를 **구현한다**」

### 4.2 진짜 문제 (한 문장)

**마방진 조건을 알고 있어도 제출 직전에 검증 항목(특히 대각선)을 빠뜨리고, 채점 실패 후 약 20분을 들여 우연히 누락을 찾아야 하는 불편이 반복된다.**

### 4.3 Mom Test 증거 3줄

1. 「채점에서 실패해서, 누락된 부분을 찾다가 **20분**이 지나서 발견했어.」
2. 「행열 맞은 건 확인했고, **대각선은 한쪽만** 하고 다른 쪽은 안 했어.」
3. 「**20분** 동안 뭔가 찾다가 **우연히** 찾았어.」

### 4.4 인사이트 요약

| 항목 | 내용 |
|------|------|
| 마지막 행동 | OO 과제 — 빈칸 2개 채우고 행·열·대각선 1개만 확인 후 제출 |
| 불편 | 제출 전 빠진 검증 인지 못함; 채점 실패 후 스스로 추적 |
| 비용 | 채점 실패 → **약 20분** 탐색 → 우연 발견 → 수정 |
| 핵심 패턴 | 조건은 **알고 있었으나** 제출 순간 체크리스트 부재; 체계적 재검증이 아닌 **우연 발견** |

## 6. 워크북 · 세션 3 (문제 정의 → 검증 루프)

> Mom Test 시뮬레이션 결과를 세션 3 스코프에 매핑. 상세 PRD: `docs/PRD.md`

### 6.1 주제 (한 문장)

**4×4 부분 마방진을 “끝냈다”고 말하기 전에, 행·열·대각선(10줄) 합 34를 빠짐없이 확인하는 규칙과 검증 루프를 만든다.**

### 6.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 부분 마방진 과제를 손·코드로 다루는 **학습자** — 빈칸 채운 뒤 **스스로 판정** |
| **Goal** | 채점/TA 피드백 **전에** “어느 줄이 34가 아닌지”를 **한 번에** 알 수 있게 함 |
| **Input** | 4×4 `int[][]` (0 = 빈칸), 값 1~16, 목표 합 **34** |
| **Output** | 10줄 합 결과 + **통과/실패** + **틀린 줄 식별** |

### 6.3 성공 기준 (Mom Test 증거 연결)

| # | 기준 | 증거 연결 |
|---|------|-----------|
| S1 | 제출 직전 **대각선 2개** 합을 반드시 계산·기록 (행만 금지) | 행만 확인 / 대각선 한쪽만 |
| S2 | 실패 시 **1분 이내** 틀린 줄(행/열/↘/↙) 식별 (15~20분 우연 탐색 금지) | 슬라이드·우연 발견 |
| S3 | Test Loop: 틀린 ↘ 대각선 → 실패, 올바른 배치 → 통과 | ↘ 36, 7·8 위치 수정 |

### 6.4 표면 문제 — 이번에 하지 않을 것

- 마방진 **자동 Solver** / 빈칸 자동 채우기
- **GridUI**, InputHandler, ResultDisplay 전체 UI
- ECB **전 클래스** 일괄 구현
- 1~16 백트래킹 **완성 마방진 탐색**

### 6.5 8계층 (세션 3 범위)

**Rule:** 4×4; 0 또는 1~16; 유효 줄 10개(행4+열4+↘+↙) 합=34; 0 남으면 완성 판정 금지; 체크리스트 `R1–R4 | C1–C4 | ↘ ↙`

**Command:** `validate`, `test`, `checklist`

**(Skill):** `magic-square-validate-before-submit` — 10줄 합 먼저, 행만 맞다고 통과 선언 금지

**Test Loop:** Red `test_wrong_diagonal_fails` → Green `test_all_lines_sum_34` → Refactor
